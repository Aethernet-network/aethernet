2026-04-23 — F4B bug closure (selection-race)
---------------------------------------------
F4B achieved selection-race bug-class closure. The F4B LogicalKeyConsumer
interface (Type E admission) keys admission on RoundID rather than event
content hash, so per-RoundID Apply fires once regardless of how many
byte-distinct TaskVerificationConsensus events the cluster emits. The
dispatcher-integrated harness at internal/verification/cross_node/
PASSES the multi-emit three-node scenario. Verdict: selection-race bug
class closed at the in-process harness grain. F4B became the combined-
branch foundation for F4C.

2026-04-23 — F5 workstream decision + three diagnostics
-------------------------------------------------------
Founder requested three read-only diagnostics before finalizing
workstream shape. D1: RecordCanonicalStake / RecordCanonicalUnstake are
NOT idempotent at API level but are guarded by transfer.Settle's atomic
state-transition barrier at the only callsite, so Divergence (A) is a
different mechanism than the TVConsensus race — defers to its own
future characterization, not F5 scope. D2: per-(consumer, key) mutex in

FailedRetryable retry loop converges the admission record (flips to

ledger divergence is PERMANENT — no self-healing. Fix is prevention,
not healing. Workstream shape: F4 stays frozen at 114d304+51bce89; F5 =
concurrent-Apply race fix (blocks F4 merge to main); F6 = silent-zero
family (queued, non-blocking); F7 = stake-manager defense-in-depth
(queued, non-blocking); Divergence (A) = separate future
characterization.
